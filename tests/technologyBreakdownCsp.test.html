renderTechnologyBreakdown — CSP-safe dynamic styling

Covers the fix for two style="..." HTML attributes (segment width/color, swatch color) that this app's CSP (style-src has no 'unsafe-inline') silently blocked. Confirmed empirically, against the exact production CSP as a real HTTP response header via Playwright/Chromium, that element.style.setProperty() is NOT restricted the same way style="" HTML attributes and setAttribute("style", ...) are (both fall under style-src's `style-src-attr` sub-directive; direct CSSOM property assignment does not) — so the fix keeps using CSSOM, it does not need generated CSS classes. This file proves the runtime output is functionally correct (right width/color per technology, via CSS custom properties) and that the style attribute CSSOM assignment leaves behind never contains a literal `width`/`background` declaration — only the intended `--breakdown-*` custom properties, which is what tools/ci/check-csp-bootstrap.js's static source scan can't see (it only checks the source text, not the rendered DOM).
