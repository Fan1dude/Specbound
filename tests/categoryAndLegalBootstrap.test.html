CSP fix — category and legal page bootstrap

Covers the production defect where all 6 category pages and all 4 static legal pages rendered completely blank: their bootstrap was a bare inline <script type="module"> block, which this app's own CSP (script-src has no 'unsafe-inline', no nonce, no hash) silently blocks. Proves the replacement external entry points (js/pages/categories/bootstrap.js, js/pages/legal/bootstrap.js) actually call loadNavbar(), loadFooter(), and (for category pages) renderCategoryPage() with the expected path prefix against a real DOM — the structural "no inline script anywhere" proof lives in tools/ci/check-csp-bootstrap.js instead, since that's a static source-scanning concern, not a runtime one.
