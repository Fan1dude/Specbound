Sitewide heading semantics

Covers two things: (1) the shared navbar brand/logo (js/core/layout.js's loadNavbar()) must never render as an <h1> or carry heading semantics, since it renders on every page and would duplicate that page's own primary heading; (2) every complete application page resolves, in its final DOM state, to exactly one meaningful, visible <h1>.

Audited complete-page set: every file under pages/**/*.html (excluding the six dynamically-rendered pages/categories/*.html pages and the auth-gated pages/feedback.html/pages/moderation.html, each covered by their own dedicated group below since their real heading only exists after JavaScript resolves), plus index.html and 404.html. design-system.html is a separate, explicitly-documented exception (Group E) — an unlinked, robots.txt-disallowed internal style-guide page whose second <h1> is a live typography-sample, not an accidental duplicate; it is pinned, not silently skipped. tests/*.test.html files are the test harness itself, not application pages, and are out of this audit's scope.
