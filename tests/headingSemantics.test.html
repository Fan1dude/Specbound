Sitewide heading semantics

Covers two things: (1) the shared navbar brand/logo (js/core/layout.js's loadNavbar()) must never render as an <h1> or carry heading semantics, since it renders on every page and would duplicate that page's own primary heading; (2) every complete application page resolves, in its final DOM state, to exactly one meaningful, visible <h1>.

Audited complete-page set: discovered automatically at run time from tests/generated/pageManifest.json (written fresh by tools/ci/generate-page-manifest.js, which reads git-tracked *.html files at the repo root plus everything under pages/ — untracked/scratch files are never included). Pages under pages/categories/ are dynamically rendered (zero static <h1> by design) and are verified by Group B instead of the generic per-page check. Any other discovered page whose raw source has zero visible <h1> but at least one hidden one (the fail-closed gated pattern) must be explicitly registered in registeredGatedPages below and is verified dynamically by Group C — an unregistered page in that state fails loudly with its path. Every other discovered page (including design-system.html, which no longer carries a second real <h1> — see Group E) must resolve to exactly one visible <h1> in its raw source. tests/*.test.html files are the test harness itself, not application pages, and are excluded by construction (the manifest generator never queries tests/).
