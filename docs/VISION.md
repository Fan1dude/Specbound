# Specbound Vision

Status: Authoritative. Approved 2026-07-28.

---

# What Specbound Is

Specbound is the permanent home for every builder's journey.

It helps builders document projects from the first idea through planning, building, testing, release, reflection, and long-term preservation.

Public message:

> Share where it starts, not just where it finishes.

Internal promise:

> If it is worth building, it is worth remembering.

---

# What Specbound Is Not

- a social-media feed
- a project showcase centered only on finished work
- a popularity contest
- an engagement-maximization product
- an AI-generated portfolio platform

Specbound is a builder-centered documentation workspace.

See `PRODUCT_PRINCIPLES.md` for the full belief system and the explicit list of features Specbound avoids.

---

# Core Philosophy

Projects are temporary. Builders are not.

The Project is the container.

The Build Log is the habit.

The Builder Archive is the long-term result.

---

# The V1 Loop

Create Project → Add Build Logs → Track Progress → Finish or Archive → Revisit Later.

Every real feature exists to serve this loop, directly or by removing friction from it.

---

# Every Feature Must Help a Builder

- start building
- continue building
- learn
- improve
- remember
- share meaningful work

If a feature does none of these, it doesn't belong in Specbound. See `SCOPE.md` for what that rules in and out for Version 1.

---

# Decision Hierarchy

When priorities conflict, choose in this order:

1. Protect builder trust.
2. Protect builder work and data.
3. Preserve knowledge.
4. Improve the building workflow.
5. Reduce complexity.
6. Improve accessibility.
7. Improve performance.
8. Expand capability.

---

# Final Quality Test

Before recommending or implementing anything, ask:

- Does this help someone build, learn, or remember?
- Does it make documentation easier?
- Does it belong inside a workshop?
- Does it preserve the builder's focus?
- Does it keep the project as the hero?
- Is it secure by default?
- Is it simpler than the alternatives?
- Will it still make sense in five years?

If not, revise the approach.
